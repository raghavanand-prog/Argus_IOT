# 04 — Evaluation protocol

Written against Arp et al. (2022), *Dos and Don'ts of Machine Learning in Computer
Security*, USENIX Security 22 — every pitfall below has an explicit response.

## Metrics

- **Detection** — per-class P/R/F1, PR-AUC (not ROC-AUC, which misleads under class
  imbalance), false positives **per device-hour** (not FPR — on a real network attack
  flows are rare, so an impressive FPR still produces an unusable alert volume; this is
  the base-rate fallacy).
- **Response** — TTD, TTC (censored, report the censoring rate), FIR per device-day,
  benign-function disruption rate, containment efficacy.
- **Evidence** — decision reproducibility rate, feature reproducibility rate, replay
  latency.
- **Calibration** — ECE, reliability diagrams, empirical conformal coverage vs nominal.

## The ablation — the central experiment

Disable the correlator, risk engine, conformal gate, and drift monitor in turn (`A1`-`A4`)
against the full system (`A0`) and a detection-only `NoOpAdapter` baseline (`A6`, the
field's actual L0 system — identical detection metrics to A0 by construction, zero
containment). The argument the table must support: `A1`-`A4` barely move F1 and
substantially move containment metrics. If it doesn't hold, that's H1/H2 refuted and
still a reportable, publishable negative result — see `MASTER-PLAN.md` §7.

## Baselines

Suricata-style signature-only reference; Isolation Forest on raw (non-baselined) flow
features (isolates the contribution of per-device baselining); Random Forest on a
published feature set (establishes the detector isn't a strawman); detection-only ARGUS
(A6, the most important baseline — same detection numbers as A0, zero containment).
Published third-party numbers are cited as context only, never tabulated next to ARGUS's
own numbers as if comparable — different splits/sampling/hardware make that meaningless.

## Arp et al. pitfalls — responses

| Pitfall | Response |
|---|---|
| Sampling bias | Documented sampling, seeds recorded |
| Label inaccuracy | Labels generated by the attack orchestrator at action time |
| Data snooping | Temporal splits, disjoint calibration set |
| Spurious correlations | Every feature carries a written justification |
| Inappropriate baseline | Detection-only (A6) baseline included |
| Inappropriate performance measure | FP/device-hour alongside F1; PR-AUC not ROC-AUC |
| Base rate fallacy | Test set preserves operational base rates |
| Lab-only evaluation | Acknowledged, not solved — stated plainly in limitations |
